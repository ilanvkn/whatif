# Independent AI team qualification — 2.1.0

Verified locally on 2026-11-10 with Node 22.23.3, Codex CLI 0.166.0-alpha.5.1, Playwright 1.65.0 and Chrome 157.0.8103.40. Only the disposable synthetic app was targeted. No company application or real customer account was tested.

## Real model experiment

Six fresh Codex sessions performed red analysis, criticism, blue repair, replay criticism, then another red/critic epoch. Provider receipts identify six different sessions and report 101,254 input-plus-output tokens across them. This includes cached input in input-token totals and is not a bill or monetary estimate. The CLI did not emit a model name, so none is inferred. Independent contexts do not establish model diversity.

The original app allowed one synthetic account to read another account's record and reported successful checkout for failed payment statuses. Red selected concrete experiments from the reviewed scenario space. Browser and synthetic-account checks reproduced failures twice. A separate critic accepted the evidence. Blue proposed an actual replacement of domain.mjs, requiring a nonempty matching string owner and an integer 200–299 payment status. The controller applied that exact replacement in an isolated Git checkout; it did not switch a fixture mode.

The same selected browser/security cases ran twice after the patch, alongside twelve fixed semantic checks for types, ownership and status boundaries. Replay and critic review accepted one repair. A second epoch ran further selected cases and stopped with no failure observed in those cases. The original source remained unchanged; the accepted source stays in the disposable checkout.

Limits for that run: 8 role attempts, 2 epochs, 10 minutes, 1,000 requests, 120 seconds per call, 40,000 prompt characters and 131,072 output bytes per call. A 120,000 reported-token threshold was checked between calls; it is not a hard token or dollar cap. The output stream is capped live; the final provider output file is size-checked after completion, not constrained by a disk quota.

## WhatIF defects found during qualification

An earlier run passed the proposed repair's replays but generated an oversized final critic prompt. The input limit stopped that review and the controller restored the original isolated source. That run is retained as failed qualification evidence, not counted as an accepted repair. The next run used compact measured evidence and completed. Tests also caught a sandbox receipt hashing the pre-filter profile; it now hashes the profile actually executed.

Source patching rejects traversal, immutable-host changes, stale base hashes, duplicate files and no-op replacements. Executed macOS checks denied outside file reads/writes, child creation and new outbound connections, while allowing the owned loopback listener. This combines macOS Seatbelt with Node permissions; it is not qualified on Linux or Windows.

Fresh-process team verification checks nested campaigns, repeated case identity, model outputs and schemas against receipts, unique session IDs, critic citations, source continuity, launch/profile/stop receipts, rollback/acceptance, usage totals and current isolated source. Unsigned local hashes establish internal consistency, not independently attested execution. An incomplete interrupted ledger is rejected rather than presented as complete evidence.

## Reproduce and extend

Follow the team commands in the README with the included agent-app fixture and configured optional browser engine. Outputs include summary.json, calls.json, epochs.json, per-call receipts and model-output.json, before/after campaign evidence, patch.json, and final-source.json. Provider outputs may vary; exact selection and usage are not deterministic. No model inference is performed by the normal unit suite.

The release has 74 passing core/control/protocol tests plus seven separately executed real-engine tests: 81 distinct tests. Fake providers in controller tests are explicitly marked and establish rollback/budget behavior only. The live qualification above uses actual Codex sessions. Full local receipts are in the project-owned release checkpoint; generated source/evidence and provider session identifiers are not shipped in the plugin.

This proves a bounded find–challenge–repair–replay loop on a small known fixture. It does not prove arbitrary-app repair, full security coverage, one-million-user capacity, human behavioral prediction or superiority over MiroFish. See the benchmark protocol for the next evidence required.
